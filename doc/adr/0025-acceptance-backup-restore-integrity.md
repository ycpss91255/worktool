# 0025 驗收設定備份的安全還原

- 狀態：已採納（2026-11-12）
- 討論：#949、#963；實作：#952。
- 依據：不變量 [ADR-0004](0004-invariant-user-content.md)「使用者寫的內容歸使用者」。

## 背景

實機驗收會暫時修改使用者設定，需要將設定還原到驗收前的狀態。備份若已損毀，或相對 cache 的工作目錄與環境在還原時改變，直接逐檔覆寫可能先傷到 live 設定，再發現問題或寫到錯誤位置。

## 決策

1. 新備份記錄可驗證的受管目標，並保存相對 cache 解析所需的原始位置。manifest 完整寫入後才公開，還原由已公開的記錄決定。
2. 還原任何檔案之前，檢查整份 manifest、備份資料、連結、受管目標與目錄紀錄；驗證與還原使用同一組目標。檢查不以 live 檔案內容必須不變為前提，因為驗收本身可能修改它。
3. 驗證失敗時拒絕還原，保留 live 設定與備份供人工檢視。舊格式若缺少足以唯一確認原目標的 metadata，也拒絕自動還原，不猜測、不自動升級或刪除備份。

## 影響與限制

此機制假設備份從檢查至還原期間不被並行修改；沒有可信簽章，無法保證偵測資料與其校驗資料遭一致竄改。舊備份也無法證明原 mode 值。這些限制不改變 ADR-0004 的不變量。

`test/unit/config_backup_restore_integrity_spec.bats` 檢查資料、連結與目錄 metadata 損毀、舊格式拒絕及不覆寫 live；`test/unit/verify_config_backup_cache_spec.bats` 檢查相對 cache 在跨工作目錄時的還原。實機呼叫端已由 #965 接線；新最終 head 的 host 實機完整流程驗收仍待執行。
