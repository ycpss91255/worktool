# 0024 milestone 驗收在完整子功能進入 main 後進行

- 狀態：已採納（2026-11-12）
- 討論：#918、#938。

## 背景

將子功能先合入 milestone 分支，會使最終驗收 PR 累積所有功能差異，難以分別審查與追溯。既有治理已要求每個子 issue 個別 PR、CI 與獨立確認，並以 milestone 驗收 PR 作為人類 gate。

## 決策

1. 將可獨立審查、完整驗證的子功能 PR 依相依順序各自合併到 main，程式、測試與相關文件隨功能一同交付。
2. 所有子功能 PR 完成後，從更新後的 main 準備 milestone 驗收 PR，僅保留人類審查清單及必要證據，不以它彙整子功能變更。
3. 驗收 PR 維持既有 milestone gate 與維護者核准紀錄；原有歷史不因本決議改寫。

## 影響與限制

人類審查的是已合入 main 的功能及驗收證據，驗收 PR 不能代替各功能 PR 的測試與審查。決議不設定 PR 行數上限，也不新增機械式範圍判定。
